## Задача 1: Обедающие философы

### Описание задачи

Пять философов сидят за круглым столом. Перед каждым философом лежит вилка. Чтобы есть, философу нужны **две вилки** (левая и правая). Философы могут думать и есть.

### Проблема

Если все философы одновременно возьмут левую вилку, они будут ждать правую вилку вечно → **deadlock**.

### Реализация

Класс `DiningPhilosophers` содержит два метода:

1. **`RunWithDeadlock()`** — демонстрация deadlock
2. **`RunWithoutDeadlock()`** — используется:
   - `SemaphoreSlim` для ограничения количества одновременно едящих философов
   - Упорядоченный захват вилок (всегда сначала вилка с меньшим номером)

### Используемые технологии

- `Thread` — для создания потоков философов
- `lock` — для синхронизации доступа к вилкам
- `SemaphoreSlim` — для ограничения количества одновременно работающих потоков

## Задача 2: Спавший парикмахер

### Описание задачи

В парикмахерской работает один парикмахер. Клиенты приходят и садятся в очередь. Если парикмахер спит (нет клиентов), клиент его будит. Очередь ограничена — если мест нет, клиент уходит.

### Реализация

Класс `SleepingBarber` использует:

- `SemaphoreSlim` — для сигнализации о приходе клиентов
- `Mutex` — для защиты критических секций (очередь, состояние парикмахера)
- `Queue<Client>` — очередь клиентов

### Используемые технологии

- `SemaphoreSlim` — для синхронизации парикмахера и клиентов
- `Mutex` — для защиты критических секций
- `Queue<T>` — потокобезопасная работа с очередью (защищена Mutex)

## Задача 3: Производитель-Потребитель

### Описание задачи

Есть буфер ограниченного размера. Производители добавляют товары в буфер, потребители забирают. Нужно:
- Не переполнить буфер
- Не пытаться забрать из пустого буфера
- Правильно синхронизировать доступ

### Реализация

Класс `ProducerConsumer` предоставляет два решения:

1. **С использованием `BlockingCollection<T>`**
2. **С использованием `SemaphoreSlim + lock`** (статический метод `RunWithSemaphore`)

### Используемые технологии

- `BlockingCollection<T>` — потокобезопасная коллекция с блокировкой
- `SemaphoreSlim` — для контроля свободных/занятых мест в буфере
- `lock` — для защиты критических секций

## Используемые технологии и библиотеки

### Основные классы .NET

- **Thread** — базовый класс для создания потоков
- **lock (Monitor)** — примитив синхронизации для критических секций
- **SemaphoreSlim** — семафор для ограничения количества одновременно работающих потоков
- **Mutex** — примитив для взаимного исключения
- **BlockingCollection<T>** — потокобезопасная коллекция с блокировкой
