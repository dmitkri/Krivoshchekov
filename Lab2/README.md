# Лабораторная работа №2

## Описание

В лабораторной исследуются следующие типы коллекций:

- **List<T>** - динамический массив
- **LinkedList<T>** - двусвязный список
- **Queue<T>** - очередь (FIFO)
- **Stack<T>** - стек (LIFO)
- **ImmutableList<T>** - неизменяемый список

Для каждой коллекции измеряется время выполнения следующих операций:

1. **Добавление элементов:**
   - В конец коллекции
   - В начало коллекции
   - В середину коллекции

2. **Удаление элементов:**
   - Из начала коллекции
   - Из конца коллекции
   - Из середины коллекции

3. **Поиск элемента по значению**

4. **Получение элемента по индексу** (если применимо)

## Используемые технологии и библиотеки

- **.NET 8.0** - платформа для разработки
- **C#** - язык программирования
- **xUnit** - фреймворк для написания автоматизированных тестов
- **System.Diagnostics.Stopwatch** - для измерения времени выполнения операций

## Инструкция по запуску

### Требования

- Установленный .NET SDK версии 8.0 или выше
- Терминал или командная строка

### Шаги для запуска

1. **Откройте терминал** в папке проекта `Lab2`

2. **Восстановите зависимости** (если нужно):
   ```bash
   dotnet restore
   ```

3. **Запустите основное приложение** для анализа производительности:
   ```bash
   dotnet run
   ```

   Приложение выполнит замеры производительности для всех коллекций и выведет результаты в консоль.

4. **Запустите автоматизированные тесты** для проверки корректности операций:
   ```bash
   dotnet test
   ```

   Или для более подробного вывода:
   ```bash
   dotnet test --verbosity normal
   ```

### Параметры тестирования

В файле `Program.cs` можно изменить следующие параметры:

- `collectionSize` - размер коллекции для тестирования (по умолчанию 100 000 элементов)
- `iterations` - количество итераций для усреднения результатов (по умолчанию 5)

Все бенчмарки запускаются через класс `CollectionBenchmarkRunner`, который обеспечивает единообразный запуск всех тестов производительности.

## Подход к реализации замеров

1. **Инициализация коллекций** - создается пустая коллекция нужного типа
2. **Заполнение данными** - коллекция заполняется заданным количеством элементов
3. **Измерение времени** - для каждой операции используется `Stopwatch` для точного измерения времени
4. **Многократное выполнение** - каждая операция выполняется несколько раз (по умолчанию 5)
5. **Усреднение результатов** - вычисляется среднее время выполнения для каждой операции
6. **Вывод результатов** - результаты выводятся в консоль в удобном формате

## Выводы и анализ результатов

### 1. List<int> (динамический массив)

**Сильные стороны:**
- **Добавление в конец** (0,384 мс) - очень быстрое благодаря амортизированной O(1) сложности
- **Получение по индексу** (0,000 мс) - мгновенный доступ благодаря прямой адресации, O(1)
- **Удаление из конца** (0,000 мс) - очень быстрое, O(1)

**Слабые стороны:**
- **Добавление в начало** (0,008 мс) - требует сдвига всех элементов, O(n)
- **Удаление из начала** (0,007 мс) - также требует сдвига, O(n)

**Вывод:** `List<T>` оптимален для операций с концом коллекции и для доступа по индексу. Не рекомендуется для частых операций с началом коллекции.

### 2. LinkedList<int> (двусвязный список)

**Сильные стороны:**
- **Добавление/удаление в начале** (0,000 мс) - мгновенные операции, O(1)
- **Добавление/удаление в конце** (0,000 мс) - также O(1)

**Слабые стороны:**
- **Добавление в конец** (2,793 мс) - медленнее, чем у List, из-за создания узлов
- **Получение по индексу** (0,281 мс) - требует последовательного прохода, O(n)
- **Поиск элемента** (0,059 мс) - также O(n), медленнее чем у List
- **Операции в середине** требуют поиска позиции, что замедляет выполнение

**Вывод:** `LinkedList<T>` идеален для частых операций вставки/удаления в начале или конце, но неэффективен для доступа по индексу и поиска.

### 3. Queue<int> (очередь FIFO)

**Характеристики:**
- **Enqueue** (0,668 мс) - эффективное добавление в конец
- **Dequeue** (0,000 мс) - быстрое удаление из начала
- **Contains** (0,004 мс) - поиск работает, но не является основной операцией

**Вывод:** `Queue<T>` специализирован для работы по принципу FIFO (первый пришел - первый ушел). Операции вне этого паттерна не поддерживаются или неэффективны.

### 4. Stack<int> (стек LIFO)

**Характеристики:**
- **Push** (0,560 мс) - эффективное добавление в начало (вершину стека)
- **Pop** (0,000 мс) - быстрое удаление из начала
- **Contains** (0,005 мс) - поиск возможен, но не является основной операцией

**Вывод:** `Stack<T>` оптимизирован для работы по принципу LIFO (последний пришел - первый ушел). Как и Queue, не предназначен для произвольного доступа.

### 5. ImmutableList<int> (неизменяемый список)

**Характеристики:**
- **Добавление в конец** (43,338 мс) - **очень медленно** из-за создания новой версии коллекции
- Все операции модификации (0,001 мс) - медленнее, чем у мутабельных коллекций
- **Поиск** (0,105 мс) - медленнее, чем у обычного List

**Вывод:** `ImmutableList<T>` обеспечивает безопасность потоков и неизменяемость, но за счет значительного снижения производительности. Используется в многопоточных сценариях, где важна безопасность данных.

### Общие выводы

1. **Для общего назначения:** `List<T>` - лучший выбор благодаря балансу производительности и функциональности.

2. **Для частых операций в начале/конце:** `LinkedList<T>` превосходит `List<T>` при работе с началом коллекции.

3. **Для специализированных структур данных:** `Queue<T>` и `Stack<T>` оптимальны для соответствующих паттернов доступа.

4. **Для многопоточности:** `ImmutableList<T>` обеспечивает безопасность, но требует компромисса в производительности.

5. **Рекомендации по выбору:**
   - Нужен быстрый доступ по индексу → `List<T>`
   - Частые вставки/удаления в начале → `LinkedList<T>`
   - Очередь задач → `Queue<T>`
   - Стек вызовов/отмена операций → `Stack<T>`
   - Многопоточность без блокировок → `ImmutableList<T>`
